# 한글코딩 놀이터 — 현황 분석 및 개선 계획

- 작성일: 2026-08-22
- 대상: `/Volumes/T7/클로드 코드 T7/클로드 대형 프로젝트/한글코딩` (React 19 + Vite 7 + TS + CodeMirror 6, 정적 배포, localStorage 저장)
- 분석 방법: 8개 관점(교육 설계 PED / 언어·인터프리터 LANG / 거북이 플레이어 TURT / UX·접근성 UX / 코드 품질·인프라 CODE / 교실 운영 CLASS / 영어 브리지·에디터 BRIDGE / 경쟁 벤치마크 BENCH)에서 93개 발견사항을 내고, 별도 검증자가 재현·반박을 시도한 결과를 반영했다. 본 문서 작성 시 `npx tsc --noEmit`(통과), `npm run smoke`(46/46 통과), 주요 주장 재현(`npx tsx`)을 다시 확인했다.

## 한 줄 결론

엔진의 의미론과 교재 텍스트는 틀린 곳이 없을 만큼 건실하지만, "미션을 바꾸면 직전 미션 코드가 사라지는" 저장 버그(critical), 공용 PC 초기화 수단 부재, `아니면`+Enter 자동완성 함정, 학습을 검증하지 못하는 미션 판정 때문에 지금 그대로 교실에 넣을 수 없다 — 다행히 치명 결함 대부분이 S~M 규모라 하루 작업으로 "교사 지도 하의 체험 수업" 수준까지는 끌어올릴 수 있다.

### 1.2 지금 상태로 교실에 투입 가능한가

**아니오.** 근거는 네 가지이며 전부 재현됐다.

1. 미션 드롭다운을 바꾸는 순간 직전 미션에 쓴 코드가 새 미션의 코드로 덮어써져 영구 유실된다 (`src/App.tsx:116-136`, `src/editor/CodeEditor.tsx:183-185`). 30명이 미션을 오가면 작품이 전부 사라진다.
2. 컴퓨터실 공용 PC에서 앞 교시 학생의 코드·뱃지·마지막 미션이 그대로 남고, 지울 버튼이 없다 (`src/storage.ts`, `src/App.tsx:105-112` — '초기화'는 그림판/출력 창만 지움). 앞 학생이 완료한 미션은 다음 학생이 풀어도 축하가 뜨지 않는다 (`App.tsx:82`).
3. 조건문 미션에서 `아니면`을 치고 Enter를 누르면 5줄짜리 `만약 … 아니면 … 끝` 스니펫이 삽입된다 (`src/editor/hangulLanguage.ts:140`, `src/editor/CodeEditor.tsx:156-162`). 한글 IME 이벤트 순서로도 재현.
4. 미션 1~3은 시작 코드를 건드리지 않고 실행만 해도 "참 잘했어요! 미션 완료!"와 색종이가 나온다 (`src/missions/missions.ts:148, 238, 347`). 반면 README가 약속한 영어 코드(`for i = 1 to 4 … end`)는 미션 3·4·6을 영원히 완료할 수 없다 (`:347, :450, :674`의 한글 문자열 검사).

위 4개(+ 파서 에러 줄 번호, 스텝 예산)를 고치면 **"교사가 옆에서 지도하는 1~2차시 체험 수업"**에는 쓸 수 있다. 한 학기 커리큘럼, 교사 진도 확인, 저사양·오프라인 교실(Google Fonts CDN 의존), 태블릿 세로 모드는 별도 작업이 더 필요하다.

## 2. 진짜 강점 (과장 없이)

- **개념 설명에 오류 0건**: 8개 미션 정독 결과 `=` vs `==`, 0-인덱스, 외각 360÷n, 144°×5=두 바퀴, `i % 6` 순환 모두 정확. 비유(상자·갈림길·레시피·기차)와 문장 길이가 9~13세에 맞다.
- **엔진 의미론 정확**: 단항 마이너스·`아니다`·`그리고/또는` 우선순위, 리스트 구조 비교와 별칭, 엄격한 조건 타입 검사, 소수 표시 반올림, 한글·이모지 글자 단위 길이. smoke 46/46, tsc 통과.
- **이중 에러 피드백**: 줄 번호 + 아이 눈높이 문장 + 에디터 빨간 물결 밑줄(대부분의 에러에서 정확한 줄).
- **플레이어 타이밍**: effectStart 이월 + clamp로 프레임이 뜸해도 벽시계 속도 유지, rAF+setTimeout으로 백그라운드 탭에서도 진행, DPR·리사이즈 시 세그먼트에서 재구성.
- **도입 장벽 0에 가까움**: 백엔드·로그인·개인정보 수집 없음, 외부 통신은 폰트 CDN뿐, `dist/` 업로드만으로 배포.
- **브리지 실행은 실제로 동작**: `if/then/else/end`, `elif`, `for/to`, `def/return`, `turtle.forward` 혼용 실행 확인. 점(.) 멤버 완성에 한글 설명 패널.
- **교재 데이터 구조**: 배우기(비유·핵심·자주 하는 실수)→따라하기([넣기])→퀴즈→도전이 `missions.ts` 데이터로 분리돼 있어 확장이 쉽다.

## 3. 핵심 문제 TOP 10 (심각도순)

> 심각도 기준: critical = 학습/사용을 막거나 틀린 것을 가르침, high = 핵심 경험을 크게 해침, medium = 개선 시 체감 큼, low = 사소. "검증" 열은 별도 검증자의 결과(확인 / 하향 / 미검증).

### 1. 미션 전환 시 이전 미션 코드가 새 미션 코드로 덮어써져 영구 유실 — critical, 확인 (CODE-1)
- **증거**: `src/App.tsx:116-119` `handleCodeChange`가 `missionId`를 클로저로 캡처해 300ms 뒤 `saveCode(missionId, code)`. `App.tsx:121-131` `handleSelectMission`이 `setMissionId(id)` 직후 `editor.setCode(...)`를 동기 호출 → `CodeEditor.tsx:183-185` updateListener가 리렌더 전 옛 `onChangeRef.current`를 부름 → 이전 미션 키에 새 미션 코드가 저장됨. 브라우저 재현 2회: 미션1 코드 → 미션2 선택 → 700ms 후 `hangul-coding:code:hello` = 미션2 starterCode.
- **영향**: 새 미션에서 300ms 안에 타이핑하지 않는 한 100% 발생. README의 "자동 저장"이 정반대로 동작하고, 아이는 원인 모를 작품 소실 + 미션1에 미션2 코드가 보이는 혼란을 겪는다.
- **개선안**: `CodeEditor.tsx`에 `const programmatic = Annotation.define<boolean>()`을 두고 `setCode`의 dispatch에 `annotations: programmatic.of(true)`, updateListener에서 `update.transactions.some(tr => tr.annotation(programmatic))`이면 onChange 생략. `App.tsx`에 `missionIdRef`(useRef)를 두어 `handleCodeChange`/`handleRun`의 `onDone`(79행, 실행 중 미션 전환 시 이전 id로 뱃지 부여하는 같은 계열 버그)이 ref를 읽게 한다. 회귀 테스트는 dev 모드 `window.__cmView`를 쓰는 브라우저 스크립트로.
- **노력**: S

### 2. 공용 PC에서 앞 학생 데이터가 그대로 남고 지울 수단이 없음 — high, 확인 (CLASS-2)
- **증거**: `src/storage.ts:3` PREFIX 고정, 키는 `code:{id}`/`last-mission`/`badges` 3종, removeItem/clear 호출 0건. `App.tsx:105-112` '초기화' 버튼은 캔버스·콘솔만 지움(title: "그림판과 출력 창을 깨끗하게 지워요"). `App.tsx:15-18`에서 앞 학생 last-mission으로 시작, `:19` 뱃지 그대로, `:82` `if (prev.has(m.id)) return prev`라 앞 학생이 완료한 미션은 다음 학생이 풀어도 색종이·뱃지가 뜨지 않음.
- **영향**: 2교시부터 "작은 성공 경험" 축이 깨진다. 교사가 복구하려면 F12 → Application → Clear storage뿐이며 README에도 안내 없음.
- **개선안 (1단계, S)**: `storage.ts`에 `clearAll()`(PREFIX로 시작하는 키만 순회 삭제) 추가, TopBar 또는 HelpModal 하단에 '처음부터 다시 시작(모두 지우기)' 버튼(confirm 후 clearAll → completed 비우기 → 미션1 starterCode 로드). `App` 초기화 시 `location.search`에 `reset=1`이 있으면 clearAll 후 `history.replaceState`로 쿼리 제거 — 교사는 `…/?reset=1` 링크만 바탕화면에 둔다. 기존 '초기화' 라벨은 '그림 지우기'로. README에 '교실에서 쓰기' 절 추가. (2단계, M: 이름 슬롯으로 PREFIX 스코프 + 진도 JSON 내보내기/가져오기)
- **노력**: S (1단계)

### 3. `아니면`을 치고 Enter를 누르면 `만약-아니면` 스니펫이 통째로 삽입 — high, 확인 (BRIDGE-3)
- **증거**: `CodeEditor.tsx:156-162` `autocompletion({selectOnOpen:true, activateOnTyping:true})` + completionKeymap Enter=acceptCompletion(Prec.highest, `:179`에 중복 등록). `hangulLanguage.ts:140` 라벨 `'만약-아니면'`이 `'아니면'`과 부분문자열 퍼지 매치되어 유일 후보로 선택됨. 브라우저 재현: 문서 끝에 `아니면` 입력 → Enter → `만약 조건 이면\n    \n아니면\n    \n끝` 삽입. 한글 IME 이벤트 순서(compositionend 후 keydown 13)로도 동일. 부수: 줄 끝 단어가 완전 일치 후보(`참`, `반환` 등)이면 Enter가 한 번 먹힘.
- **영향**: 미션 3 도전·자유 코딩에서 `아니면` 줄을 직접 치면 거의 100% 재현, 5줄 플레이스홀더 블록을 초등학생이 복구하기 어렵다.
- **개선안**: (1) `hangulLanguage.ts:140`을 `snippetCompletion('만약 ${조건} 이면\n    ${}\n아니면\n    ${}\n끝', { label: '만약', displayLabel: '만약 ~ 아니면', detail: '조건 + 아니면', type: 'keyword' })`로 바꿔 매칭 라벨에서 '아니면'을 제거(detail이 달라 중복 제거되지 않음). (2) `hangulCompletionSource`에서 입력 단어와 label이 완전히 같고 apply가 없는 후보는 제외하거나, `autocompletion({defaultKeymap:false})` + 커스텀 키맵으로 Tab=수락, Enter는 실제 텍스트 변화가 있을 때만 수락(VS Code "smart"). (3) `CodeEditor.tsx:179`의 `...completionKeymap` 중복 제거. '끝/아니면/이면' 단순 항목 추가는 역효과(Enter no-op)이므로 하지 않는다.
- **노력**: S

### 4. 미션 완료 판정이 학습을 검증하지 못함 — medium (PED-1 · CLASS-3 · BENCH-6 · CODE-2 · UX-9 통합)
- **증거**: `missions.ts:148`(hello: print≥1), `:238`(variables: print≥2 + 대입 정규식), `:347`(condition: print≥1 + `code.includes('만약')&&includes('이면')`) → starterCode 그대로 실행 시 3개 모두 check=true(재현). `:450` `code.includes('반복')`, `:674` `includes('함수')`, `:776` `includes('[')` → 주석 `# 만약 이면`만으로도 통과, 반대로 README 예시 영어 코드(`for i = 1 to 4 … end`, 8 effects)는 check=false(재현). square starter 주석에 '반복'이 있어 반복 없이 수동 4회 작성해도 통과. 미션 3 starter는 "아쉬워요, 다시 도전!"과 "참 잘했어요! 미션 3 완료!"가 동시에 뜸. `App.tsx:80-97` check 실패 시 아무 메시지 없음(조용한 실패). 앱 안에서 영어 모드를 권장(ConsolePane.tsx:32, HelpModal.tsx:77-79)하므로 영어로 쓴 아이는 영문 모른 채 뱃지를 못 받는다.
- **영향**: 미션 1~3 보상이 공허해지고, 교재의 '자주 하는 실수'(반복 밖에 쓰기)로도 통과되며, 영어 브리지는 성공인데 미완료라는 틀린 피드백을 준다. (뱃지는 localStorage 전용 자기동기 장치이므로 "교사가 진도 판단 불가"는 과장 — 검증자 하향 사유.)
- **개선안 (통합 결론)**: AST 전달(M) 대신 이미 export된 `src/lang/lexer.ts` `tokenize()`로 키워드 집합을 만든다(영어→한글 정규화·주석·문자열 제거가 자동). `run.ts`는 그대로 두고 `MissionCheckInput`에 `starterCode`를 추가해 `App.tsx:80`에서 전달. 헬퍼: `kws(code)`(keyword 토큰 Set), `hasOp(code,'[')`, `notStarterResult(effects, starterEffects)`(starter 실행 효과 JSON과 같으면 실패). 교체안 — hello: print/say 텍스트 중 '여기를 바꿔 보세요'가 아닌 것 ≥1; variables: 대입 정규식 + print 텍스트에 '여기에 이름' 없음; condition: `kws.has('만약')` + '딩동댕' 분기 실행 증거(print 텍스트) 또는 starter와 다른 효과; square/star: `kws.has('반복')` + 기존 효과 조건; function: `kws.has('함수')` + moves≥8; list-colors: `hasOp('[')` + 색 3종 + moves≥3. `code.trim() !== starterCode.trim()` 단순 비교는 공백만 바꿔도 뚫리므로 쓰지 않는다. 따라하기 [넣기] 코드는 설계상 통과해야 하므로 smoke에 "starter=실패, 마지막 step=성공, 영어판=성공, 주석만=실패" 케이스를 고정. `App.tsx`에 check 실패 시 `'실행은 잘 됐어요! 미션 목표를 다시 확인해 보세요: ' + m.goal` 한 줄.

### 5. 교재가 가르치는 실수와 엔진 에러가 어긋남 — medium (PED-5 · LANG-4 · LANG-5 · LANG-6 통합)
